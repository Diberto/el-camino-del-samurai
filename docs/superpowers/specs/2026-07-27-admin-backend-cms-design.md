# E-Camino-Del-Samurai: Admin Backend, CMS & User Management Specification

## Overview
This specification details the architecture and implementation for an Administration Backend, Content Management System (CMS) with Blog, Media Processing (WebP conversion + YouTube embeds), dynamic section and GPU configuration management, and User Management for the *El Camino del Samurai* project.

---

## 1. System Architecture & Multi-Database Abstraction Layer

### 1.1 Architecture Pattern
The frontend (built with Vite HTML/JS/CSS) communicates with a unified `DatabaseService` abstraction layer.

```
                  ┌────────────────────────┐
                  │    Admin / Public UI   │
                  └───────────┬────────────┘
                              │
                  ┌───────────▼────────────┐
                  │    DatabaseService     │
                  │   (Adapter Interface)  │
                  └───────────┬────────────┘
                              │
      ┌───────────────────────┼───────────────────────┬───────────────────────┐
      │                       │                       │                       │
┌─────▼──────┐         ┌──────▼─────┐          ┌──────▼─────┐          ┌──────▼─────┐
│ PocketBase │         │Local SQLite│          │  Supabase  │          │  Firebase  │
│ (Default)  │         │ (Adapter)  │          │ (Adapter)  │          │ (Adapter)  │
└────────────┘         └────────────┘          └────────────┘          └────────────┘
```

### 1.2 Database Adapters
1. **PocketBase (Default Provider)**: Uses the official PocketBase SDK / REST endpoints for Auth, CRUD operations, and file storage.
2. **Local SQLite Adapter**: Operates via local API endpoints or client-side web-SQLite for self-hosted offline/lightweight environments.
3. **Supabase & Firebase Adapters**: Configurable provider drivers implementing the standard `DatabaseAdapter` interface:
   - `login(email, password)`
   - `logout()`
   - `getCurrentUser()`
   - `getSettings()`
   - `saveSettings(settingsData)`
   - `getPosts(filter)`
   - `savePost(postData)`
   - `deletePost(id)`
   - `getUsers()`
   - `saveUser(userData)`
   - `uploadMedia(file, type)`

## 2. Database Schemas & Data Structures

### 2.1 Collection / Table: `settings`
Stores dynamic landing configurations.
- `id`: string (primary key)
- `key`: string ("site_config")
- `sections_toggle`: JSON `{ "hero": true, "philosophy": true, "gallery": true, "gpu": true, "blog": true, "contact": true }`
- `navigation_menu`: JSON `[ { "id": 1, "label": "Inicio", "url": "#hero", "visible": true }, ... ]`
- `gpu_config`: JSON parameters matching `gpu-config.js` schema (preset, shaders, particle count, quality settings)
- `updated_at`: timestamp

### 2.2 Collection / Table: `posts`
Stores blog articles.
- `id`: string (primary key)
- `title`: string
- `slug`: string (unique)
- `excerpt`: text
- `content`: HTML text (generated by WYSIWYG editor)
- `cover_image`: string (URL to WebP image)
- `youtube_video_id`: string (optional, YouTube video embed ID)
- `status`: string ("draft", "published")
- `author_id`: string (relation to `users`)
- `created_at`: timestamp
- `updated_at`: timestamp

### 2.3 Collection / Table: `users`
Stores system accounts.
- `id`: string (primary key)
- `email`: string (unique)
- `name`: string
- `role`: string ("admin", "editor")
- `active`: boolean
- `created_at`: timestamp

## 3. Media Processing & WYSIWYG Editor

### 3.1 WebP Converter Engine (`webp-converter.js`)
- Client-side image processing utilizing HTML5 `<canvas>` and `toBlob('image/webp', quality)`.
- Automatically intercepts image uploads (drag-and-drop or file selector) in the WYSIWYG editor.
- Converts PNG/JPG/GIF/BMP files to high-performance `.webp` format before sending to storage, reducing payload sizes by up to 80%.

### 3.2 WYSIWYG Editor Module (`wysiwyg-editor.js`)
- Rich text editing controls (Heading levels, Bold/Italic/Underline, Lists, Blockquotes, Alignment).
- **YouTube Embed Tool**: Embeds responsive `<iframe>` containers given any YouTube URL or Video ID.
- **Media Upload Manager**: Uploads images (converted to WebP) and video files, inserting them as semantic HTML tags.

## 4. Admin Dashboard Modules (`/admin.html`)

### 4.1 Login & Auth Guard
- Login interface at `/admin.html`.
- Session persistence via token storage.
- Auto-redirect for unauthenticated users trying to access protected views.

### 4.2 Module 1: Sections & Menu Manager
- Interactive toggle controls for enabling/disabling landing page sections (`index.html`).
- Drag-and-drop / list editor for top navigation links.

### 4.3 Module 2: GPU Settings Controller
- Visual controls for GPU engine parameters defined in [gpu-config.js](file:///d:/Documentos/Work/hummus/samurai/el-camino-del-samurai/gpu-config.js) and [gpu-panel.js](file:///d:/Documentos/Work/hummus/samurai/el-camino-del-samurai/gpu-panel.js).
- Real-time preview and save action.

### 4.4 Module 3: Blog CMS
- List view of posts with search, status filters (published/draft), and pagination.
- Create/Edit view featuring the WYSIWYG editor, WebP cover generator, and YouTube video embed fields.

### 4.5 Module 4: User Management
- User listing with role indicators and status badges.
- Create new user / Edit role / Reset password / Deactivate user functionality.

## 5. Public Landing Page Integration (`index.html` & `blog.html`)

- `script.js` fetches dynamic settings on load:
  - Hides/shows sections according to `sections_toggle`.
  - Renders dynamic navigation menu based on `navigation_menu`.
  - Applies updated GPU configurations to `gpu-panel.js`.
- Public Blog Section (`blog.html` / embedded container): Displays published articles with responsive YouTube embeds and WebP image rendering.
